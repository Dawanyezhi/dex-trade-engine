# DEX 优先级排序策略

## 1. 分层规则

Solana DEX 聚合路由可以按交易源头、可控性和延迟划分为三层：

```text
High:   Pump.fun / Moonshot / Raydium Launchpad（内盘）
Medium: Raydium AMM/CPMM/CLMM, Meteora, PumpAMM（AMM/CLMM）
Low:    Jupiter, AlphAggregator（聚合器）
```

这个排序不是简单按报价金额排序，而是按生产系统里的综合执行质量排序：

```text
越接近一手流动性、越可控、越低延迟，优先级越高；
越依赖外部聚合、越黑盒、越不可控，优先级越低。
```

在本项目中，对应 `dexwallet.DexPriority` 的三层模型：

- `PriorityHigh`: 内盘 / Bonding Curve / Launchpad。
- `PriorityMedium`: AMM / CPMM / CLMM。
- `PriorityLow`: 第三方聚合器。

## 2. High：内盘 / 发射平台优先

`Pump.fun`、`Moonshot`、`Raydium Launchpad` 这类协议是新币发行和早期交易阶段的一手流动性入口，优先级最高。

主要理由：

- 价格来源最直接，不依赖聚合器索引和路由更新。
- 新币覆盖最快，launchpad 阶段通常早于 AMM 池子和聚合器收录。
- 交易路径最短，适合抢新币、早期买入和迁移前交易。
- 状态可控性强，可以直接读取 bonding curve、launch pool、迁移状态和平台账户。
- 失败原因更容易解释，便于做风控、告警和降级。

典型适用场景：

- 新币刚发射。
- bonding curve 阶段。
- launchpad 内盘阶段。
- token 尚未毕业到 AMM。
- 需要极低延迟的买入或卖出。

生产关注点：

- 必须检测 token 是否已经毕业或迁移。
- 已毕业 token 不应继续走内盘 builder。
- 要实时校验 curve 状态、剩余流动性、手续费和交易开关。
- 对抢新场景要结合优先费、贿赂服务和严格滑点保护。

## 3. Medium：AMM / CPMM / CLMM 第二优先

`Raydium AMM/CPMM/CLMM`、`Meteora`、`PumpAMM` 属于公开链上池子流动性。它们排在 Medium，不是因为不重要，而是因为它们更适合已经进入公开流动性阶段的资产。

主要理由：

- 流动性真实透明，可以直接读取池子账户。
- quote 可由本地计算，便于验证和回放。
- 交易构建可控，可以精确控制指令、账户、ComputeBudget、ALT 和滑点。
- 适合成熟 token、大额 Swap、稳定交易对和可解释路由。
- 相同优先级下，可以按 `outAmount`、价格影响、手续费和失败率做竞争。

为什么低于内盘：

- 新币早期可能还没有公开 AMM 池子。
- AMM 池子通常是 launchpad 毕业或迁移后才出现。
- CLMM/DLMM quote 依赖 tick、bin、bitmap 等复杂状态，池子索引和缓存要求更高。
- 对极早期资产，池子发现速度通常慢于源头协议。

典型适用场景：

- 已毕业 token。
- 成熟交易对。
- 大额交易。
- 稳定币路径。
- 需要直接控制交易构建和模拟的场景。

生产关注点：

- 池子索引必须可靠，不能只依赖静态列表。
- CLMM/DLMM 要处理 tick array、bin array、bitmap 缺失和账户过多问题。
- 需要做池子缓存、状态刷新和异常流动性过滤。
- 大额交易必须计算价格影响和拆单风险。

## 4. Low：聚合器兜底

`Jupiter`、`AlphAggregator` 这类聚合器放在 Low，不表示它们差，而是表示在自建交易引擎里它们更适合作为兜底和补充。

聚合器优势：

- 覆盖面广。
- 多跳路由能力强。
- 长尾 token 更容易找到路径。
- 接入成本低。
- 可以补齐自建 DEX 暂未覆盖的流动性。

为什么默认优先级最低：

- 外部 API 依赖强，存在限流、抖动和不可用风险。
- 路由逻辑相对黑盒，失败原因不一定可解释。
- quote 和 swap transaction 构建链路更长，延迟更高。
- 对新币收录存在索引延迟。
- 聚合器生成交易可能包含复杂账户、ALT、多跳路径、wrap/unwrap SOL、动态滑点和平台费。
- 自建系统对 ComputeBudget、tip、Token2022、私有发送和账户裁剪的控制力较弱。

典型适用场景：

- 自建协议不支持的 token。
- AMM/CLMM 主路径失败。
- 多跳路径明显优于单池路径。
- 长尾资产交易。
- 用户对成交速度不敏感的普通 Swap。

生产关注点：

- 聚合器结果必须二次模拟和校验 `minOut`。
- 要限制聚合器交易大小、账户数量、ALT 依赖和最大跳数。
- 要监控外部 API 延迟、错误率、quote 新鲜度和成交偏差。
- 不能把聚合器当作唯一主路径，否则核心交易能力会被外部服务绑定。

## 5. 为什么不能只按输出金额排序

只按 `outAmount` 排序在 demo 中简单，但在生产 DEX 系统里风险很大。

举例：

```text
Pump.fun 内盘:     输出 980 tokens，延迟低，可直接构建
Raydium AMM:       输出 1000 tokens，链上池子透明
Jupiter 聚合器:    输出 1010 tokens，多跳路由，依赖外部 API
```

如果只看输出金额，会选择 Jupiter。但真实执行时可能遇到：

- quote 过期。
- route 构建失败。
- 外部 API 超时。
- 多跳路径中某一跳滑点超限。
- 交易账户过多导致体积过大。
- ALT 缺失或不可用。
- 交易无法方便地加入自定义 tip 或 ComputeBudget。
- 实际到账低于预期。

因此生产排序应该先看优先级层级，再在同层内比较输出金额：

```text
第一层：DEX 优先级
第二层：输出金额 / minOut
第三层：价格影响
第四层：延迟和成功率
第五层：费用和风险因子
```

## 6. 推荐选择逻辑

基础策略：

```text
1. 先判断 token 生命周期阶段。
2. 未毕业或仍在 launchpad 阶段，优先 High。
3. 已毕业或已有主流池子，优先 Medium。
4. High / Medium 不支持、失败或报价显著差时，降级 Low。
5. 聚合器报价明显更优时，可以动态提升，但必须经过风险校验。
```

可以采用以下决策规则：

| 条件 | 选择 |
|------|------|
| token 仍在 bonding curve / launchpad | High |
| token 已毕业且有可靠 AMM/CLMM 池子 | Medium |
| 主路径不支持该交易对 | Low |
| 主路径模拟失败且错误可降级 | 下一个优先级 |
| 聚合器输出明显更高且通过校验 | 动态允许 Low 胜出 |
| 高优先级返回不可降级业务错误 | 终止，不继续低优先级 |

不可降级错误示例：

- 用户余额不足。
- token 被风控禁止。
- 交易金额低于最小限制。
- token account / mint 状态异常。
- 用户滑点参数非法。

可降级错误示例：

- 当前 DEX 不支持该交易对。
- 池子不存在。
- 池子流动性不足。
- DEX API 或 RPC 临时超时。
- 构建器缺少某个可替代账户。

## 7. 生产监控指标

优先级策略上线后，需要监控：

- 各优先级层级的命中率。
- 各 DEX 的报价成功率。
- 各 DEX 的构建成功率。
- 各 DEX 的模拟失败率。
- High 降级到 Medium / Low 的比例。
- Medium 降级到 Low 的比例。
- 聚合器兜底成功率。
- 聚合器报价与实际成交偏差。
- 同 token 生命周期阶段和最终选中 DEX 是否匹配。
- 不可降级错误是否被错误降级。
- 各层级平均延迟和 P95/P99 延迟。

告警建议：

- High 层连续失败，说明新币源头协议或索引可能异常。
- Medium 层失败率升高，说明池子缓存、账户解析或 RPC 可能异常。
- Low 层占比异常升高，说明自建路由覆盖或稳定性下降。
- 聚合器成交偏差异常，说明 quote 新鲜度或交易构建存在风险。

## 8. 面试表达

可以这样说明：

```text
这个优先级不是按报价金额简单排序，而是按生产 DEX 里的可控性、延迟、流动性源头和失败可解释性排序。

High 层是 Pump.fun、Moonshot、Raydium Launchpad 这类内盘或发射平台，它们是新币最早的一手流动性入口，索引最快、路径最短、状态最可控。

Medium 层是 Raydium、Meteora、PumpAMM 这类 AMM/CLMM，适合已毕业或成熟 token，池子透明、quote 可本地验证、交易构建可控。

Low 层是 Jupiter、AlphAggregator 这类聚合器，覆盖面强但依赖外部 API、路由黑盒、延迟更高，所以更适合兜底、多跳路径和长尾资产。

生产系统不能只看 outAmount。高优先级路径即使输出略低，也可能因为低延迟、可控性强、失败可解释、交易更稳定而更适合作为主路径。聚合器只有在主路径失败，或者报价明显更优且通过模拟和风控校验时才动态胜出。
```

## 9. 总结

这套排序背后的工程原则是：

- 一手协议优先于二手聚合。
- 内盘 / 新币源头优先于公开池子。
- 直接构建优先于外部构建。
- 低延迟和可控性优先于黑盒最优报价。
- 同优先级内再比较输出金额和价格影响。
- 聚合器作为兜底和补充，而不是核心交易能力的唯一依赖。

最终目标不是让每一笔交易理论报价最高，而是让 DEX 交易系统在真实生产环境里更稳定、更可解释、更可控，并且在新币、成熟币和长尾资产之间有清晰的降级路径。
